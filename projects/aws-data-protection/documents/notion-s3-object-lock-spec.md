**要点**

- WORM（Write Once Read Many）は、「一度書いたデータは、決めた条件を満たすまで、誰も消すことも書き換えることもできない」という保存の仕方です。S3 では **Object Lock** という機能で実現します。ここでの書き換えは、すでにあるバージョンの中身を変えることです。同じキーへの上書きは、新しいバージョンを足すだけなのでできます。
- 保護されるのは、バケットでもファイル名（キー）でもなく、**オブジェクトのバージョン 1 つ 1 つ**です。そのため、バージョニングが前提です。
- 保護されている間も、**通常の削除と上書きはできます**。どちらも新しいもの（削除マーカーや新しいバージョン）を足すだけで、保護されているバージョンは残るからです。消せなくなるのは、「バージョンを指定した削除」です。
- 保護の種類は 3 つ（固定の保持期間・イベントホールド・リーガルホールド）、強さは 2 段階（ガバナンスモード・コンプライアンスモード）あります。
- **一度有効にすると、バケットから Object Lock を外せず、バージョニングも止められません。**

## 1. WORM と S3 Object Lock

### 1.1 何を防ぐのか

S3 のバージョニングを有効にすると、通常の削除や上書きをしても、元のバージョンが最新ではないバージョンとして残ります。誤って消しても戻せます。

ただし、権限のある人やプログラムは、**バージョンを指定して、データを完全に消す**ことができます（バージョンを指定した削除）。バージョニングだけでは、これを防げません。Object Lock は、この「バージョンを指定した削除」を、権限があってもできないようにする仕組みです。

### 1.2 Object Lock の下で、何ができて何ができないか

| 操作 | Object Lock で保護されているバージョンがあるとき |
|---|---|
| 読み取り | できる |
| 新しく書く・同じキーに上書きする | できる。新しいバージョンができるだけで、保護されている元のバージョンは残る |
| 通常の削除（バージョンを指定しない `DeleteObject`） | できる。削除マーカー（「消した」という印のバージョン）が置かれるだけで、保護されているバージョンは残る |
| **バージョンを指定した削除**（`DeleteObject` に `VersionId`） | **できない**（`403 Access Denied`）。例外はガバナンスモードの迂回だけ（4 章） |
| 削除マーカーの削除 | できる。削除マーカーは保護されない。消すと、元のバージョンがまた「最新のバージョン」に戻る |
| バケットの削除 | できない。保護されているバージョンが残っている限り、バケットを空にできない |

### 1.3 保護する単位

設定する場所は、バケットとバージョンの 2 つです。フォルダ（プレフィックス）ごとの設定はありません。S3 にはフォルダの実体がなく、キーの文字列の一部にすぎないためです。

| 単位 | 何を設定するか |
|---|---|
| バケット | Object Lock を使えるようにすること（**有効化**。戻せない）と、新しく書かれたバージョンに自動で付ける保持の値（**既定の保持設定**） |
| バージョン | 保護される単位。保持の状態（モード・保持期限・イベントホールド）と、リーガルホールドを、バージョンごとに持つ。同じキーでも、バージョンが違えば状態も違う |

一部のプレフィックスだけを保護したいときは、既定の保持設定を使わずに、バージョンごとに保持を付けます（書き込むときに指定するか、S3 Batch Operations でまとめて付ける）。それでも有効化はバケット全体に効くので、保護しないプレフィックスも含めて、バージョニングは止められなくなります。

## 2. エンティティと属性

Object Lock に関わるものを、「何に（エンティティ）」「どんな値が付き（属性）」の形で並べます。操作（メソッド）は 5 章です。

```
S3 バケット
├─ バージョニング ……………………………………… Object Lock の前提。有効にしたあとは止められない
├─ Object Lock の設定（PutObjectLockConfiguration）
│   ├─ ObjectLockEnabled: Enabled ……………… 有効化。一度有効にしたら戻せない
│   └─ Rule.DefaultRetention ……………………… 既定の保持設定（無くてもよい）
│        ├─ Mode: GOVERNANCE / COMPLIANCE …… モード
│        ├─ Days / Years ………………………………… 固定の保持期間
│        └─ DefaultEventHold.Days …………………… イベントホールドの、解除後の保持期間
├─ バケットポリシー ………………………………………… バケットとバージョンに対する操作（5 章）を、誰が呼べるかを絞る
└─ キー（いわゆるファイル名）
     └─ バージョン（VersionId）…………………… ★ 保護される単位
          ├─ 保持（retention）
          │   ├─ Mode ……………………………………… GOVERNANCE / COMPLIANCE
          │   ├─ RetainUntilDate ………………………… 保持期限
          │   ├─ EventHold: ON / OFF ………………… イベントホールド
          │   └─ EventHoldDuration.Days ………… 解除後の保持期間
          └─ LegalHold: ON / OFF ………………………… リーガルホールド（保持とは別のフラグ）
     （削除マーカーもバージョンの 1 つだが、保持もリーガルホールドも付かない）
```

- **既定の保持設定は、書き込みの時点でバージョンに写されるだけです。** あとでバケットの既定を変えたり外したりしても、すでにあるバージョンの保持は変わりません。既存のバージョンを保護するには、バージョンごとに保持を付けます（S3 Batch Operations の `PutObjectRetention`）。
- **バージョンが保護されているのは、次のどれかに当てはまる間です。**
  1. `LegalHold` が `ON`
  2. `EventHold` が `ON`
  3. 今の時刻が `RetainUntilDate`（保持期限）より前

## 3. 保護の 3 種類

1 つのバージョンに、保持（固定の保持期間かイベントホールド）とリーガルホールドの両方を付けられます。

| 種類 | いつまで保護するか | 外し方 | 向いている用途 |
|---|---|---|---|
| **固定の保持期間**（fixed retention） | 決めた日時（`RetainUntilDate`）まで | 期限が来れば自然に外れる。延ばすことはいつでもできる | 保存期間が決まっているデータ |
| **イベントホールド**（event hold。AWS の説明では variable retention period＝可変の保持期間） | 解除するまで。解除すると、そこから決めた日数（1 日〜100 年）保護する | `PutObjectRetention` で `EventHold: OFF` にする。解除しても、決めた日数はさらに保護される | 期限を前もって決められないデータ。「消すと決めてから N 日は戻せる」形にしたいとき |
| **リーガルホールド**（legal hold） | 外すまで | `PutObjectLegalHold` で `OFF` にする。外した瞬間に保護がなくなる | 監査・訴訟などでの一時的な凍結 |

- イベントホールドは 2026-09-08 に追加された機能です。追加の料金はかかりません。
- 保持期限の上限は 100 年です。

### 3.1 イベントホールドの状態の移り変わり

```
 書き込み（既定の保持設定から EventHold: ON が付く）
   │
   ▼
 ┌────────────────────┐
 │ イベントホールド中      │  RetainUntilDate は「読んだ時刻＋日数」と表示され、
 │ EventHold: ON        │  読むたびに先へ動く。期限は来ない（検証済み）
 └─────────┬──────────┘
           │ 解除（PutObjectRetention で EventHold: OFF）
           ▼
 ┌────────────────────┐
 │ 解除後の保持期間        │  RetainUntilDate が「解除した時刻＋日数」で固まる（検証済み）
 │ EventHold: OFF       │  この間にもう一度 ON にできる（検証済み）
 └─────────┬──────────┘
           │ RetainUntilDate を過ぎる
           ▼
 ┌────────────────────┐
 │ 保護なし              │  バージョンを指定した削除・ライフサイクルの失効で消える
 └────────────────────┘
```

### 3.2 イベントホールドとリーガルホールドの違い

どちらも、外すまで消せません。いちばんの違いは、外したあとです。イベントホールドは決めた日数だけ保護が続き、リーガルホールドはすぐ消せるようになります。

| | イベントホールド | リーガルホールド |
|---|---|---|
| どこにあるか | 保持の一部（`PutObjectRetention`） | 保持とは別のフラグ（`PutObjectLegalHold`） |
| モード | 必須（ガバナンス / コンプライアンス） | 無い |
| バケットの既定にできるか | できる（既定の保持設定の `DefaultEventHold`） | **できない**。書き込むたびに付ける |
| ON の間 | 消せない。ガバナンスモードなら迂回で消せる | 消せない。**迂回も効かない** |
| 外したあと | **決めた日数は消せない** | **すぐ消せる** |
| 外せる主体 | `s3:PutObjectRetention` の権限を持つ主体 | `s3:PutObjectLegalHold` の権限を持つ主体 |
| もともとの用途 | 「出来事が起きるまで保護し、起きてから N 日保護する」（契約の終了など） | 訴訟・監査での一時的な凍結 |

## 4. 2 つのモード

保持（固定の保持期間とイベントホールド）には、モードがあります。リーガルホールドにはモードがありません。

| | ガバナンスモード（`GOVERNANCE`） | コンプライアンスモード（`COMPLIANCE`） |
|---|---|---|
| 保護されているバージョンの削除・保持期限の短縮 | 迂回の権限（`s3:BypassGovernanceRetention`）を持ち、リクエストで迂回を指定したときだけできる | **誰もできない。root もできない** |
| ガバナンスモードを外す | 迂回でできる | — |
| コンプライアンスモードへ移す | できる。迂回が要るかは試していない（未検証） | — |
| モードを外す・ガバナンスモードへ戻す | — | できない |
| 設定を誤ったとき | 迂回の権限を持つ人が直せる | **直せない。期限まで保存の費用がかかり続ける**。期限前に消す方法は、AWS アカウントを閉じることだけ |
| 用途 | ほとんどの人には消させないが、いざというときは直せるようにしたい | 規制などで、絶対に消させてはいけないデータ |

### 4.1 迂回（ガバナンスモードだけ）

ガバナンスモードの保持は、次の 2 つがそろうと無視できます。

- 呼び出す主体が `s3:BypassGovernanceRetention` の権限を持つ。
- リクエストに `x-amz-bypass-governance-retention: true` のヘッダーを付ける（CLI では `--bypass-governance-retention`）。

- **`s3:BypassGovernanceRetention` は `s3:*` に含まれます。** S3 の全権限を持つ主体（AWS 管理ポリシーの `AdministratorAccess` や `AmazonS3FullAccess` を持つものなど）は、迂回できます。止めたいときは、バケットポリシーで `s3:BypassGovernanceRetention` を Deny します。全員に Deny すると、誰も迂回できなくなります（検証済み）。
- **S3 のコンソールは、迂回のヘッダーを自動で付けます。** 権限を持つ人がコンソールから消すと、ガバナンスモードの保持は効きません。API や CLI では、明示しない限り迂回されません。
- 迂回はリーガルホールドには効きません。

### 4.2 モードとイベントホールドの解除

- ガバナンスモードでは、イベントホールドの解除に迂回は要りません（検証済み）。`s3:PutObjectRetention` の権限があれば解除できます。
- AWS のドキュメントでは、コンプライアンスモードでもイベントホールドは解除できます（未検証）。解除したあとの日数は、コンプライアンスモードでは誰にも縮められません。

## 5. 操作（メソッド）

### 5.1 バケットに対する操作

| 操作（IAM の権限） | 何をするか | Object Lock との関係 |
|---|---|---|
| `CreateBucket`（`ObjectLockEnabledForBucket`） | 作るときに有効にする | バージョニングも同時に有効になる |
| `PutObjectLockConfiguration`（`s3:PutBucketObjectLockConfiguration`） | 既存のバケットで有効にする。既定の保持設定を入れる・変える・外す（`Rule` の無い設定を入れると外れる） | 既存のバージョンには効かない |
| `GetObjectLockConfiguration`（`s3:GetBucketObjectLockConfiguration`） | 設定を読む | |
| `PutBucketPolicy`（`s3:PutBucketPolicy`） | この表とバージョンに対する操作（5.2）を、誰が呼べるかを Deny で絞る | ガバナンスモードでは、迂回の Deny をここに書く |
| `PutBucketLifecycleConfiguration`（`s3:PutLifecycleConfiguration`） | 失効（自動で消す設定）を入れる | 保護されているバージョンは、失効で消えない（検証済み） |
| `PutBucketVersioning`（`s3:PutBucketVersioning`） | バージョニングを有効にする・止める | Object Lock を有効にしたバケットでは止められない |
| `DeleteBucket`（`s3:DeleteBucket`） | バケットを消す | 保護されているバージョンが残る限り、空にできないので消せない |

### 5.2 バージョンに対する操作

| 操作（IAM の権限） | 何をするか | 保護されているときの挙動 |
|---|---|---|
| `PutObject`・`UploadPart`（`s3:PutObject`） | 新しいバージョンを作る | 保持は、明示のヘッダー（`x-amz-object-lock-*`）が無ければ既定の保持設定から付く。**チェックサムのヘッダーが必須**（6.2）。保持の値を明示して書くには、`s3:PutObjectRetention`（リーガルホールドなら `s3:PutObjectLegalHold`）の権限も要る |
| `CopyObject`・`UploadPartCopy`（`s3:PutObject`） | コピーで新しいバージョンを作る | 保持は上と同じ。チェックサムなしでも通る（検証済み） |
| `PutObjectRetention`（`s3:PutObjectRetention`） | 保持を変える | 固定の保持期間を延ばす・イベントホールドを付ける・解除するは、迂回なしでできる。固定の保持期間を縮める・モードを外すは、ガバナンスモードなら迂回が要り、コンプライアンスモードではできない。イベントホールド中に日数を変えても、保持期限は前へは戻らない。`Mode` を省くと `MalformedXML`（検証済み） |
| `PutObjectLegalHold`（`s3:PutObjectLegalHold`） | リーガルホールドを付け外す | 保持とは関係なく、いつでもできる |
| `GetObjectRetention`・`GetObjectLegalHold`・`HeadObject` | 状態を読む | |
| `DeleteObject`（`VersionId` なし。`s3:DeleteObject`） | 削除マーカーを置く | **常に通る**。バージョンは残る |
| `DeleteObject`（`VersionId` あり。`s3:DeleteObjectVersion`） | バージョンを消す | **拒まれる**。ガバナンスモードの迂回だけが例外 |
| `PutObjectTagging`（`s3:PutObjectTagging`・`s3:PutObjectVersionTagging`） | タグを付ける | 保護されていても変えられる。中身ではないため |

### 5.3 まとめて操作する: S3 Batch Operations

既存のたくさんのバージョンに保持を付ける・解除するには、S3 Batch Operations を使います。

- 対象の一覧（マニフェスト。`Bucket,Key,VersionId` の CSV か S3 インベントリ）を渡し、1 つの操作（保持の設定・リーガルホールド・タグ付けなど）を全件に行います。1 つのジョブで行える操作は 1 種類です。
- ジョブは、作った人ではなく、**ジョブに渡した IAM ロール**の権限で動きます。ジョブを作るには、そのロールを渡す権限（`iam:PassRole`）が要ります。
- 保持を付けるジョブのロールに、迂回の権限は要りません（検証済み）。
- マニフェストは、ジョブを作るときに ETag で固定されます。あとで差し替えても、ジョブは差し替えた中身では動きません。
- タグ付けの操作は、そのバージョンのタグを丸ごと置き換えます。

## 6. 周辺の機能との関係

### 6.1 ライフサイクル

- 保護されているバージョンは、ライフサイクルの失効（`Expiration`・`NoncurrentVersionExpiration`）で消えません（検証済み）。
- 最新のバージョンの失効は、削除マーカーを置くだけです。これは保護されていても動きます（検証済み）。
- ストレージクラスの移動（Intelligent-Tiering など）は、そのまま動きます。
- 保持期限が切れたバージョンは、ライフサイクルで消えます。「イベントホールドを解除して日数を待ち、ライフサイクルで消す」という使い方ができます。

### 6.2 書き込み（チェックサム）

保持が付く書き込み（既定の保持設定があるバケットへの書き込みを含む）では、**`Content-MD5` かチェックサムのヘッダー（`x-amz-checksum-*`）が必須**です。無いと `InvalidRequest: Content-MD5 OR x-amz-checksum- HTTP header is required` で拒まれます（検証済み）。マルチパートアップロードでは、パートごとに要ります。

| 書き方 | 通るか（検証済み） |
|---|---|
| AWS CLI の既定 | 通る（版によって Content-MD5 か CRC のチェックサムを付ける） |
| boto3 1.35 の既定 | 通る（Content-MD5 を付ける） |
| boto3 1.36 以降の既定 | 通る（CRC32 をトレーラーで付ける） |
| boto3 1.36 以降で `request_checksum_calculation="when_required"` | **拒まれる**（何も付けなくなる） |
| `CopyObject`・`UploadPartCopy` | 通る（チェックサムなしでも） |
| 署名付き URL（presigned URL）、boto3 の既定 | **拒まれる**。既定の署名は SigV2 で、保持が付く書き込みには SigV4 が要る（`Put Object requests with Object Lock parameters require AWS Signature Version 4`） |
| 署名付き URL、SigV4 で、発行のときに `ContentMD5`（か `ChecksumCRC32`）を署名に入れ、同じヘッダーを付けて PUT | 通る |
| 署名付き URL、SigV4 で、チェックサムを署名に入れずに発行し、PUT のときにヘッダーだけ足す | **拒まれる**（`AccessDenied`。署名されていないヘッダー） |

### 6.3 通知

- バージョンの保持の変更（付ける・解除する・Batch Operations での設定）は、EventBridge に `Object Retention Updated` のイベントとして届きます（検証済み）。解除は `event-hold: OFF` で見分けられます。イベントの時刻から届くまで 0〜2 秒でした（検証済み）。
- 拒まれた保持の変更は、このイベントには出ません（検証済み）。
- バケットに対する操作（バケットポリシーの変更など）は、CloudTrail の管理イベント（EventBridge では `AWS API Call via CloudTrail`）として届きます。**拒まれた試みも届きます**（検証済み）。

### 6.4 そのほか

- **暗号化に使う KMS キー（AWS KMS key）は、Object Lock では保護されません。** 利用者が管理する KMS キーで暗号化していると、キーが削除されたとき、バージョンは残っていても読めなくなります。
- レプリケーションと組み合わせるときは、複製先のバケットでも Object Lock を有効にする必要があります。
- Object Lock を有効にしたバケットは、S3 サーバーアクセスログの書き込み先にできません。

## 7. 費用

- Object Lock の機能そのものに、追加の料金はありません。
- **保護されているバージョンは消せないので、その間の保存の費用が必ずかかります。** イベントホールドなら、解除してから決めた日数の分も残ります。
- 既存のバージョンに保持を付ける費用は、S3 Batch Operations（ジョブあたり $0.25 ＋ 100 万オブジェクトあたり $1）と、バージョンごとの `PutObjectRetention` のリクエスト（PUT の料金。S3 Standard で 1,000 件あたり $0.005）の合計です。

## 8. 似た機能との違い

| 機能 | 何を保護するか | 特徴 |
|---|---|---|
| **S3 Object Lock** | S3 のオブジェクトのバージョン | この資料の対象 |
| S3 Glacier Vault Lock | 旧来の Glacier の「ボールト」（S3 の Glacier ストレージクラスとは別物） | ボールトのポリシーを一度ロックすると変えられない。今の S3 のバケットには使えない |
| AWS Backup Vault Lock | AWS Backup のバックアップ | コンプライアンスモードでは、猶予期間のあとロックを外せない。原本とは別に、消せない写しを持つ形 |

## 9. 検証済みのこと（2026-11-02〜05）

検証用のバケット（原本バケットと同じ AWS アカウント tuscenes-prod に作ったもの。ガバナンスモード、既定の保持設定はイベントホールド 1 日）で確かめました。

| # | 確かめたこと | 結果 |
|---|---|---|
| Q1 | 既定の保持設定を、イベントホールドだけで設定できるか | できた。書いたバージョンにはガバナンスモード・イベントホールド ON・1 日が付いた |
| Q2 | ガバナンスモードの迂回で、イベントホールド中のバージョンを消せるか | **消せた**。迂回なしのバージョンを指定した削除は拒まれた |
| Q3 | イベントホールドの解除に迂回が要るか | 要らなかった。解除後は「解除した時刻＋1 日」まで消せなかった |
| Q5 | チェックサムのヘッダーの無い書き込みが拒まれるか | 拒まれた（1 回の書き込みも、マルチパートのパートも） |
| Q6 | S3 Batch Operations で、既存のバージョンにイベントホールドを付けられるか | できた。ジョブのロールに迂回の権限は要らなかった |
| Q7 | バケットポリシーで迂回を全員に Deny すると、迂回できなくなるか | 誰も迂回できなくなった。書き込み・上書き・通常の削除は通った |
| Q8 | 解除したあと、もう一度イベントホールドを付けられるか | できた。保持期限は付け直した時刻から数え直しになった |
| Q9 | ライフサイクルの失効が、保護されているバージョンを消さないか | 消さなかった。最新のバージョンには削除マーカーが付いただけ |
| Q10 | 保持の変更が EventBridge に届くか | `Object Retention Updated` として届いた。0〜2 秒 |
| Q11 | バケットの設定の変更が EventBridge に届くか | 管理イベントとして届いた。拒まれた試みも届いた |
| Q12 | イベントホールド中に、保持期限が過ぎてしまわないか | 過ぎない。保持期限は「読んだ時刻＋日数」と表示され、読むたびに先へ動く |
| Q13 | 書き込みの方法ごとに通るか | 6.2 の表 |

未検証のこと:

- 既存のバケットに、後から Object Lock を有効にしたときの振る舞い（検証は、作るときに有効にしたバケットで行った）。
- コンプライアンスモード（Q4。そのため 9 章の表に Q4 は無い）。
- S3 Batch Operations での、イベントホールドの解除（Q6 は付ける側だけ）。

## 10. 用語

| 用語 | 意味 |
|---|---|
| WORM | Write Once Read Many。一度書いたら、決めた条件を満たすまで消すことも書き換えることもできない保存の仕方 |
| S3 Object Lock | S3 で WORM を実現する機能 |
| バージョン（`VersionId`） | 同じキーに書くたびにできる、オブジェクトの 1 つ 1 つ。Object Lock で保護される単位 |
| キー | オブジェクトの名前（いわゆるファイル名）。暗号化の鍵とは別物 |
| 主体 | AWS の操作を行う IAM のユーザーやロール |
| ETag | オブジェクトの中身から S3 が計算する値 |
| SigV2・SigV4 | AWS のリクエストの署名の方式。SigV4 が新しい |
| S3 インベントリ | バケットのオブジェクトとバージョンの一覧を、定期的にファイルで出す機能 |
| 最新のバージョン・最新ではないバージョン | 1 つのキーに複数のバージョンがある場合に、キーを指定して読んだときに返るものが最新のバージョン（current version）。それ以外が最新ではないバージョン（noncurrent version） |
| 削除マーカー（delete marker） | 通常の削除で置かれる「消した」という印のバージョン。Object Lock では保護されない |
| 有効化 | バケットで Object Lock を使えるようにすること（`ObjectLockEnabled: Enabled`）。戻せない |
| 既定の保持設定（`DefaultRetention`） | 新しく書かれたバージョンに自動で付ける保持の値 |
| 保持（retention） | バージョンごとの保護の状態。モード・保持期限・イベントホールドの組 |
| 保持期限（`RetainUntilDate`） | この日時まで消せない、という期限 |
| 固定の保持期間（fixed retention） | 決めた日時まで保護する保持 |
| イベントホールド（`EventHold`） | 解除するまで保護し、解除してから決めた日数保護する保持。AWS の説明では variable retention period（可変の保持期間） |
| 解除後の保持期間（`DefaultEventHold.Days`・`EventHoldDuration.Days`） | イベントホールドを解除してから保護する日数 |
| リーガルホールド（`LegalHold`） | 保持とは別の ON / OFF のフラグ。外すまで消せず、外せばすぐ消せる |
| ガバナンスモード（`GOVERNANCE`） | 迂回の権限を持つ主体だけが、保持を無視できるモード |
| コンプライアンスモード（`COMPLIANCE`） | root を含めて誰も保持を無視できないモード |
| 迂回（governance bypass） | ガバナンスモードの保持を無視すること。`s3:BypassGovernanceRetention` の権限と `x-amz-bypass-governance-retention` ヘッダーの両方が要る |
| 失効（expiration） | ライフサイクルで自動に消すこと。保護されているバージョンは消えない |
| S3 Batch Operations | 一覧で指定したたくさんのオブジェクトに、同じ操作をまとめて行う機能 |
| マニフェスト | S3 Batch Operations に渡す、対象の一覧 |
| チェックサムのヘッダー | 書き込む中身が壊れていないことを確かめる値（`Content-MD5`・`x-amz-checksum-*`）。保持が付く書き込みでは必須 |
| 署名付き URL（presigned URL） | 認証情報を持たない相手に、決まった操作を一時的に許す URL |
