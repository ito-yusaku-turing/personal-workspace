- 前提: [permission-model.md](../done/s3-data-protection-2/permission-model.md)（層・ハッチ H1〜H5・抜け穴 X1〜X5・範囲）、[current-state.md](../done/s3-data-protection-2/current-state.md) の 6 章（弱点 W1〜W16。2026-10-30 時点で、WORM の前）

**要点**

- 第二弾で 9 本に Object Lock を入れ終えた（2026-11-16）。残った抜け穴を、次の 3 つに分ける（伊藤、2026-11-16）。
  - **区分 A**: 緊急ハッチ、または正式な削除の手段として、意図して残すもの。監視もする。
  - **区分 B**: 残る抜け穴だが、監視を仕込むもの。
  - **区分 C**: 残る抜け穴で、監視もされていないもの。
- **今は、ほぼすべてが区分 C。** 書き込みの記録（トレイル）はあるが、起きても人に届く通知がまだ無いため（通知の PR は第 3 段階）。
- 第三弾で、塞ぐもの（手順 D・掃除）を消し、残すものに通知を付けて A か B にする。**それでも C に残る見込みのものは L11・L18・L21**（GitHub の側、新しいバケット、写しが無いこと）。どこまでやるかを決める。

## 区分の決まり

| 区分 | 条件 |
|---|---|
| A | 意図して残す（ハッチ・正式な手段）。だれが使えるか（名簿）が分かり、使ったら通知が届く |
| B | 意図はしないが残す。起きたら通知が届く（届かなければ見張りで気づく） |
| C | 起きても、だれにも届かない。記録が残るだけのものも C に数える |
| 塞ぐ | 第三弾で、その道自体を無くす（SCP・バケットポリシー・主体の削除） |

「監視」は、**起きたら人に届くこと**を指す。トレイルや Inventory に記録が残るだけでは、監視に数えない（後から調べられるだけ）。

## 小さな SCP（2026-11-20、検討中）

手順 D から切り出して先に入れる。#2643 で外した通知（通知の部品・IAM ロールの変更）の代わりの予防。**着手の目安: 2026-11-27（来週中、伊藤）**。置き場は cdk-apps の `apps/organization-policy`。

| 文 | 拒むもの | 例外 | 台帳 |
|---|---|---|---|
| 通知の部品 | 名前が `original-bucket-alert` で始まるルール・SNS のトピック・発行のロール・Amazon Q Developer の設定の変更・削除 | deploy の経路（cfn-exec-role） | L12 |
| 監査の証跡 | `original-bucket-audit` の停止・削除・変更 | deploy の経路 | L12 |
| ジョブのロール | `original-bucket-lock-batch` の信頼・権限の変更。`iam:PassRole` は L2（完全削除用の権限の持ち主）に絞る | deploy の経路（ロールの変更）、L2（PassRole） | L5 |
| スタック | `stack/OriginalBucket*` の `UpdateStack`・`DeleteStack`・`CreateChangeSet`・`ExecuteChangeSet` | GitHub Actions の deploy のロール | L10（このアプリの分） |

- 入れるまでのあいだ、L5・L12 は C のまま（空白）。いちばん大きい空白は、3 本目（A-1）が入るまでホールドの解除がどこにも届かないこと。3 本目は #2643 のマージの後すぐに出す。
- 確かめること: `chatbot:*` をリソース単位で絞れるか、SCP の大きさの余裕、管理アカウントの SCP の今の文（Control Tower の証跡の保護を含む）。
- **要件 9・10 からの逸脱**: 要件 9 は、例外に届く権限の変更（拒否された試みを含む）を数分以内に通知することを求める。IAM ロールの変更の通知を外したので、IAM の分は「SCP で予防に替える。拒否された試みは拾わない」とする（2026-11-20、伊藤）。
