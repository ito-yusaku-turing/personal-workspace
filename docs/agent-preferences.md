# エージェントの自律範囲と個人プリファレンス

コーディングエージェントが「明示的な指示がなくてもやってよいこと／いけないこと」を、開発者ごとに設定する仕組みを定める。設定は **git 管理外のファイル**に置き、エージェントが作業開始時に読んで振る舞いを調整する。

リポジトリのルール（personal-workspace では [`git-workflow.md`](git-workflow.md)、ほかのリポジトリではその `AGENTS.md` 等）が上位にあり、**個人設定でそれを解禁することはできない**。個人設定でできるのは、リポジトリのルールが個人設定に委ねている操作（commit / push / PR 作成など）を緩めるか、さらに締めることだけ。

## 設定ファイル

| 項目 | 値 |
|---|---|
| パス（コンテナ内） | `$HOME/.personal-workspace/agent-preferences.md` = `/usr/home/.personal-workspace/agent-preferences.md` |
| パス（ホスト） | `$USER_HOME_DIR/.personal-workspace/agent-preferences.md` |
| 雛形 | `docker/config/agent-preferences.example.md`（`docker/bin/setup.sh` が配置する） |
| 形式 | Markdown（人間が読み書きしやすく、自由記述も混ぜられる） |

コンテナ HOME 配下に置くため、**リポジトリには入らず、他の開発者にも共有されない**。また devbox にマウントした他リポジトリでの作業にも同じ設定が効く。

> なぜリポジトリ内ではなくコンテナ HOME か: これは「その人がどう働きたいか」であって、リポジトリの仕様ではない。git 管理外であることがパスから自明で、`docker/bin/setup.sh` の配置先とクレデンシャル置き場（`$USER_HOME_DIR`）に揃う。

## 運用の原則 — 書くのは「既定から外れたいこと」だけ

**初期状態はすべて `特になし`**。開発者がエージェントと作業していて不便を感じたとき（毎回同じ確認をされる／勝手にやってほしくないことをされる）に、**その項目だけ**を書き換える。最初から埋めさせない。

**既定の自律範囲はリポジトリのルール側**（`AGENTS.md` の「既定の自律範囲」と [`git-workflow.md`](git-workflow.md) の操作ごとの既定表）が持つ。個人設定は**その差分だけ**を持つ。

したがって、**リポジトリのルールが既に要求していることは個人設定に書かない**。書かせると二重管理になり、食い違ったときにどちらが正か分からなくなる。典型例:

- ビルド / lint / 型チェック / テストの実行（動作確認は必須）
- 生成物の再生成（同一コミットに含めることが必須のもの）
- personal-workspace でセッションを終えるときの commit と push（リポジトリのルールで確認なしに行う。止めたいときは `git push` を `都度確認` / `禁止` にする）
- git 管理外のローカル設定ファイルを上書き・削除しないこと（リポジトリのルールでの禁止）

## 設定値

各操作に次の4値のいずれかを与える。

| 値 | エージェントの振る舞い |
|---|---|
| `特になし` | 既定に従う（**初期値**。commit / push / PR 作成は「依頼時に実行」） |
| `常に許可` | 指示がなくても実行してよい。実行後に何をしたかを報告する |
| `都度確認` | 実行前に許可を取る |
| `禁止` | 依頼されても実行せず、手順の提示にとどめる |

**設定ファイルが無い場合、該当項目の記載が無い場合、`特になし` の場合は既定に従う**。読めない・壊れている場合も同様で、エラーにはせず既定で動く。

## 記入例の書き方（無効化の記法）

**ファイルに書かれている内容はすべて有効な指示として扱う。** 記入例・メモ・一時的に外した項目は **HTML コメントで囲む**。

```markdown
<!-- これは記入例。エージェントは読み飛ばす -->
```

- 「例」「サンプル」といった語を本文に添えても**無効にはならない**。有効な指示と機械的に区別できないため。
- 雛形は**判断の分かれる行を含めない**。設定項目の初期値は `特になし`、純粋な例示は HTML コメントに入れる。

> この記法は、雛形の `（例）` 付きの行が「未編集の残骸か有効な指示か」判別できず、実際に解釈が揺れたことを受けて定めた。とくに「ローカル設定ファイルを削除しない」が例示扱いだと、一般の削除許可に負けて上書きされうる。個別の禁止が一般の許可に勝つとしても、そもそも曖昧さを残さないほうがよい。なお、この種の禁止事項自体は個人の好みではないため、リポジトリのルール（`AGENTS.md`）に置く。

## エージェントの義務

1. **作業開始時に設定ファイルを読む**（セッションにつき1回でよい）。
2. 該当する操作の直前に、リポジトリのルールと個人設定の**両方**を確認する。リポジトリのルールで禁止されているものは、個人設定が `常に許可` でも実行しない。
3. `常に許可` に基づいて自律実行したときは、**何をしたかを必ず報告**する（黙って実行しない）。
4. 設定ファイルに書かれていない種類の操作で、取り消しにくいもの・外部に影響するものは、`都度確認` 相当として扱う。
5. **設定ファイルをエージェントが勝手に書き換えない**。変更したい場合は人間に提案する。
6. **HTML コメント内は指示として読まない**（記入例やメモのため）。
7. 一般的な許可と個別の禁止が衝突する場合は、**個別の禁止を優先**する。あわせて曖昧さを人間に報告し、記述の修正を提案する。

## 記載する項目

雛形は次の区分で構成し、**全項目の初期値を `特になし`** にしてある。項目を増やしてもよい（エージェントは書かれている内容を尊重する）。

| 区分 | 設定できるもの |
|---|---|
| Git / GitHub 操作 | `git commit`（このリポジトリ / 他リポジトリ）、`git push`、`gh pr create`、コメント・レビュー投稿 |
| リポジトリの操作 | 依存の追加・更新、ファイル削除、マイグレーション適用、他リポジトリへの書き込み |
| そのほか行ってよいこと・いけないこと | 箇条書きの自由記述 |
| 作業の進め方の好み | 「実装前に方針を提示してほしい」等の自由記述 |

force push などリポジトリのルールで禁止されている操作は、雛形の設定対象に含めない。

`git commit` は**このリポジトリと、マウントした他リポジトリを別の行に分けて**書く。他リポジトリの規約はこのリポジトリからは見えないため、行が1つだけだとどこまでを許可したのか読み取れない。

マウントした他リポジトリでのブランチの扱い（`main` にコミットしてよいか等）は、そのリポジトリの規約が決める。個人設定で緩めても、そのリポジトリの規約で禁止されている操作は実行しない。

## 設定の変え方

```bash
docker/bin/shell.sh                       # devbox に入る
${EDITOR:-vi} ~/.personal-workspace/agent-preferences.md
```

雛形が未配置の場合は次で置かれる（**既にあるファイルは上書きしない**）。`docker/bin/setup.sh` も初回セットアップの一部として同じ配置を行うが、あちらはホスト専用のため devbox の中からは実行できない。

```bash
docker/bin/setup/config.sh                  # ホストから
docker/container-bin/setup/config.sh        # devbox の中から
```

配置状況は `docker/bin/doctor.sh`、または `setup/config.sh status` で確認できる。

> 雛形の側が更新されても、既存の個人設定ファイルには反映されない（勝手に上書きしないため）。`setup/config.sh status` が雛形へのパスを表示するので、必要な行だけ自分で取り込む。
